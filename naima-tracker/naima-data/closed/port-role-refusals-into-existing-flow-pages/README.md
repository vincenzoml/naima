# Port role refusals into existing flow pages first

An audit of a comparable method found roles rare when named explicitly but daily as refusals built into flows (a release manager refusing to judge its own gate, a lead developer owning the merge train) — correcting an earlier read that treated roles as a central mechanism.

Why: the refusal is the valuable part, and it is cheaper inside the flow pages that already exist than as a new plugin.

Done: each relevant flow page (release, merge/coordinate) states its role's refusal in one line. A roles plugin (see the companion item) is lower priority than this.
