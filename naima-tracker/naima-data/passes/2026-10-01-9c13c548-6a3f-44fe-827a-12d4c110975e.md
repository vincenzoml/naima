Fixed the Windows fresh-install defect (bugs/fresh-naima-init-fails-windows-git-s): runningCommit() in naima/src/core/cli.ts compared git's forward-slash --show-toplevel directly against real()'s native-separator path, so a fresh Windows clone was never recognized as its own and naima init refused with 'not a clone with an origin'. Added nativePath() (naima/src/core/git.ts), the inverse of gitPath(), and a regression test (test/git.test.ts) that simulates the Windows separator on every runtime. Proof: pushed claude/w1-windows and ran .github/workflows/install.yml on it — install (windows-latest) green (run 36825829887), alongside ubuntu-latest and macos-latest. Linked tests/install-workflow-passes-ubuntu-macos-windows (set runBy=build, it needs the CI runner) as verifies of the bug. Local gates (deno task verify, node --test, bun test --timeout 30000) all green before and after. Unrelated: the push-triggered 'ci' workflow's bun job on macos-15 hit two 5000ms test timeouts (bun's default, not the 30000ms used in the gates) — matches the already-tracked bugs/bun-s-5-second-default-test-timeout, not touched here. Claim released.
